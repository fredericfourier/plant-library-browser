# Botanical image verification

Plants whose botanical image needs a human check are listed as `pending_review` in
`data/botanical-verification.json` (generated by `tools/import_botanical_assets.py` in the
border-designer repo from the bundle manifest). Each record pins `imageSha256`, the SHA-256 of
the public WebP. An approval only counts while it carries the same hash, so replacing an image
with different bytes silently drops the old approval (the importer also resets the record and
keeps the previous state under `previous`).

## Why a service is needed
GitHub Pages is static. Approvals must be shared across devices and must never ship a GitHub
token in frontend code, so approvals are written through a small service (`server/approvals-worker.js`,
Cloudflare Worker + KV) that checks a private approver key and the posted hash against the published baseline.

## Deploy
1. Create a KV namespace and bind it as `APPROVALS`.
2. Set secret `APPROVER_KEY` (long random string), vars `BASELINE_URL`
   (`https://fredericfourier.github.io/plant-library-browser/data/botanical-verification.json`) and `ALLOW_ORIGIN`
   (`https://fredericfourier.github.io`).
3. Deploy the worker, then set `apiBase` in `data/verification-config.json` to the worker URL and push.
4. The first Approve click on a device asks for the approver key (kept in sessionStorage for the tab only).

Until `apiBase` is set the Approve button is disabled and says so; nothing is stored locally.
